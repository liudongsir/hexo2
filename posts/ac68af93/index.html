springbootadmin

使用场景

应用实时运维监控, 主要监控应用状态, 根据应用的状态变化进行告警;

实时查看应用日志,线上排查问题;

完整流程

SBA采用 客户端主动心跳+服务端主动拉取 双向校验机制,确保健康状态准确.

graph TD
    A[SBA 客户端（被监控应用）] -->|1. 定时心跳（默认10s）| B[SBA 服务端]
    B -->|2. 记录心跳时间，标记“存活”| C[服务端实例注册表]
    B -->|3. 主动拉取（默认10s）| A
    A -->|4. 调用自身 /actuator/health 端点| D[应用健康检查组件]
    D -->|5. 返回健康状态（UP/DOWN/OUT_OF_SERVICE）| A
    A -->|6. 把健康状态返回给 SBA 服务端| B
    B -->|7. 对比状态：若变化（如 UP→DOWN）| E[触发告警（邮件/钉钉）]
    B -->|8. 若超时无心跳/健康状态 DOWN| F[标记实例状态为 DOWN]

流程说明:

  1. 客户端心跳(主动报活)

    • 客户端间隔 period向SBA服务端发送一个简单的HTTP请求,内容仅包含应用基本信息;
    • 这个心跳是轻量请求,不包含健康信息,用于快速报活

  2. 服务端主动拉取(校验健康)

    • SBA服务端间隔instance-probing-period时间访问客户端的 /actuator/health
    • 客户端收到请求,执行自身的监看检查逻辑(检查数据库,redis,磁盘,==自定义检查项==),然后返回完整的健康状态(UP正常, down 异常, out_of_service 服务不可用)

  3. 状态判断与告警

    • 服务端对比本次和前次的健康状态,
    • 如果客户端超过status-lifetime时间没有发送心跳,且服务端拉取健康状态失败,服务端会将该实例标记为OFFLINE并触发告警.

健康检查数据

默认检查项(无需额外配置)

检查项 作用
diskSpace 检查磁盘剩余空间（默认阈值：100MB，不足则 DOWN）
ping 基础存活检查（只要应用能响应请求，就是 UP）
db 检查数据库连接（配置了数据源则自动开启）
redis 检查 Redis 连接（引入 Redis 依赖则自动开启）
kafka/rabbitmq 检查消息队列连接（引入对应依赖则自动开启）

配置检查颗粒度(客户端)

management:
  endpoint:
    logfile:
    	# 查看日志路径
      external-file: ./logs/${spring.application.name}/console.log 
    health:
      show-details: always  # 显示所有检查项的详情（默认仅当 DOWN 时显示）
      show-components: always  # 显示所有组件的健康状态
  health:
    # 自定义磁盘空间阈值（剩余不足 500MB 则 DOWN）
    diskspace:
      threshold: 524288000
    # 禁用某个检查项（比如不需要检查 Redis）
    redis:
      enabled: false

自定义健康检查项目

package org.dromara.modules.monitor;

/**
 * @author: noob
 * @description :
 * @Date : 10:58 2026/2/27
 */

import org.springframework.boot.actuate.health.Health;
import org.springframework.boot.actuate.health.HealthIndicator;
import org.springframework.stereotype.Component;
import java.net.HttpURLConnection;
import java.net.URL;

// 自定义健康检查：检查第三方支付接口是否可用
@Component
public class PaymentApiHealthIndicator implements HealthIndicator {

    @Override
    public Health health() {
        try {
            URL url = new URL("https://api.payment.com/health");
            HttpURLConnection conn = (HttpURLConnection) url.openConnection();
            conn.setRequestMethod("GET");
            conn.setConnectTimeout(3000);

            if (conn.getResponseCode() == 200) {
                // 健康状态：UP，附带详情
                return Health.up().withDetail("payment-api", "可用").build();
            } else {
                // 健康状态：DOWN，附带错误信息
                return Health.down().withDetail("code", conn.getResponseCode()).withDetail("msg", "支付接口不可用").build();
            }
        } catch (Exception e) {
            // 健康状态：DOWN，附带异常信息
            return Health.down(e).withDetail("msg", "支付接口连接失败").build();
        }
    }
}

使用配置

启动sba服务端

在客户端中引入依赖开启配置;

sba服务端通过固定接口定时访问客户端查询状态

客户端配置

spring:
  boot:
    admin:
      client:
        url: http://localhost:8080  # SBA 服务端地址
        period: 5000  # 心跳间隔改为 5 秒（单位：毫秒）
        connect-timeout: 3000  # 连接超时 3 秒
        read-timeout: 5000  # 读取健康状态超时 5 秒

服务端配置

spring:
  boot:
    admin:
      server:
        instance-probing-period: 5000  # 主动拉取健康状态间隔 5 秒
        status-lifetime: 20000  # 超时阈值改为 20 秒（客户端 20 秒没心跳则判定为下线）

关键说明

建议「客户端心跳间隔」≤「服务端主动拉取间隔」≤「超时阈值」，比如 5s → 5s → 20s；

频率不宜设置过小（如 1 秒），会增加 SBA 服务端和客户端的网络 / CPU 开销；

若客户端网络不稳定，可适当调大「超时阈值」，避免误判应用下线。

==超时阈值主要是服务端主动拉取的阈值, 如果超过时间客户端未心跳,会触发服务端的主动拉取,如果超时未响应,则会触发服务down状态==

总结:

  1. 核心频率 客户端心跳 服务端拉取 都可以自定义 默认都是10s 超时阈值15s
  2. 客户端心跳->服务端拉取->客户端自建->服务端判断状态并告警;
  3. 检查内容 包含 应用 磁盘 内存 数据库 redis 等组件, 支持自定义健康检查 和自定义通知

说明:

其自带告警主要用于应用的down 告警,一些数据告警例如cpu使用过高 需要自定义Notifier 自主处理消息发送; (应用存活、健康状态告警) 运维类告警

prometheus 告警可以根据指标触发,例如cpu使用过高,可以自定义告警规则进行消息发送.(性能、业务指标告警) 性能类告警
