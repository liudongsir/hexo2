MCP 开发要点指南

发表于2026-06-03|更新于2026-06-12|AI
|字数总计:2.3k|阅读时长:9分钟|阅读量:

简单记录

mcp 是一系列规范协议

  • mcp调用(内置在智能体中)

  • mcp 服务(主要开发的能力端 mcp服务)

  • mcp注册 即配置json(将服务启动方式)

MCP 开发要点指南

一、MCP介绍

MCP 本身是开源免费的协议，但围绕它已经形成了一个庞大的生态系统。这个市场的运行逻辑类似于 “App Store + API 经济” 的混合体：

mcp 的多种运行协议:

python npx uvx url 网络连接;

mcp 的调用流程

graph LR
    User[用户] -->|自然语言指令| Agent[AI Agent / LLM]
    Agent -->|1. 意图识别 & 规划| Agent
    Agent -->|2. 标准 JSON-RPC 请求| MCP_Client[MCP Client]
    MCP_Client -->|3. 路由到对应服务| MCP_Server_A[GitHub MCP]
    MCP_Client -->|3. 路由到对应服务| MCP_Server_B[数据库 MCP]
    MCP_Server_A -->|4. 返回结构化结果| MCP_Client
    MCP_Server_B -->|4. 返回结构化结果| MCP_Client
    MCP_Client -->|5. 汇总上下文| Agent
    Agent -->|6. 生成最终回复/执行下一步| User

mcp 和智能体结合

  1. 动态工具发现： Agent 启动时，通过 MCP 协议自动扫描已连接的 Server 列表，获取所有可用工具的名称、描述、参数Schema。Agent 不需要硬编码知道有哪些工具，而是“即插即用”地感知能力。
  2. 标准化上下文注入： Agent 在执行复杂任务时，需要实时数据（如当前股价、用户历史订单）。MCP 的 Resources 原语允许 Agent 以统一格式读取这些数据作为推理上下文，而不需要为每个数据源写解析器。
  3. 安全隔离与权限控制： Agent 可能产生幻觉或误操作。MCP 协议层可以实施细粒度权限管控（例如：Agent 只能读取文件，不能删除；只能查询数据库，不能修改）。这解决了 Agent 落地企业最大的安全顾虑。
  4. 多 Agent 协作的桥梁： 当多个 Agent 协作时，它们可以通过共享同一个 MCP Server 来交换状态和数据。MCP Server 成为了 Agent 之间的“共享内存”或“消息总线”

一、mcp 概念

1. 配置文件 (Configuration)

MCP 的配置通常以 JSON 格式存在（如 mcp.json），用于告诉 AI 宿主（Host）如何启动和连接你的 MCP Server。

  • 本地部署 (Local / stdio)

    ：适合个人工具或读取本地文件。通过命令行直接拉起服务进程。

    • 核心字段：command (启动命令，如 python 或 npx)、args (脚本路径及参数)、env (环境变量)。

  • 远程部署 (Remote / SSE or HTTP)

    ：适合云端服务或多用户共享。通过 HTTP/SSE 协议连接。

    • 核心字段：url (远程服务的 HTTP/WebSocket 地址)、headers (鉴权信息)。

  • 作用域与位置：配置文件可以放在项目根目录（随代码提交，团队共享），也可以放在用户全局目录（如 ~/.cursor/mcp.json，仅自己可见）。

本地运行配置文件
{
  "mcpServers": {
    "MySQL": {
      "command": "uvx",   //npx python 等等 都需要本地安装所需的环境   启动程序命令
      "args": [	// 命令行启动参数
        "--from",
        "mysql-mcp-server",
        "mysql_mcp_server"
      ],
      "env": { 			//进程运行的环境变量（数据库账号密码、密钥全放这里）
        "MYSQL_HOST": "localhost",
        "MYSQL_PORT": "3309",
        "MYSQL_USER": "ryshebei",
        "MYSQL_PASSWORD": "123123",
        "MYSQL_DATABASE": "ry-shebei"
      }
    }
  }
}  
远程调用配置文件

{
  "mcpServers": {
    "my-remote-mcp-service": {
      "url": "https://your-mcp-server.example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-api-key-here",
        "Content-Type": "application/json"
      }
    }
  }
}

2. MCP 服务 (Server) 与 客户端 (Client)

在开发视角下，两者的职责划分非常明确：

  • MCP Server (你开发的“插件”)

    • 本质：一个轻量级的独立程序，负责暴露具体的能力。
    • 三大核心能力
      1. **Tools (工具)**：让 AI 执行操作（如写文件、查数据库、调用 API）。
      2. **Resources (资源)**：向 AI 提供只读的上下文数据（如日志文件、API 文档、代码库内容）。
      3. **Prompts (提示词)**：预设的模板或工作流，引导 AI 更好地使用上述工具和资源。

  • MCP Client (AI 软件的“联络员”)

    ：

    • 本质：内置在 Cursor、Claude Desktop 等宿主软件中的通信代理。
    • 职责：它遵循 1:1 专属连接原则，即一个 Client 专门负责与一个 Server 建立持久化会话，处理握手、转发请求和接收响应。

3. 调用协议 (Communication Protocol)

MCP 的底层通信高度标准化，确保了不同语言和平台之间的互通性。

  • 消息格式：统一采用 JSON-RPC 2.0。所有的请求（Request）、响应（Response）和通知（Notification）都是标准的 JSON 对象。

  • 传输模式

    ：

    • **Stdio (标准输入输出)**：最常用。AI 宿主通过子进程的方式启动你的 Server，并通过进程的 stdin/stdout 进行通信。适合本地、低延迟场景。
    • **SSE / Streamable HTTP (服务器发送事件)**：适合远程调用。Server 作为一个独立的 Web 服务运行，Client 通过 HTTP 长连接与其交互，支持服务端主动推送消息。

4. MCP 能力如何注册与获取

MCP 最大的亮点是动态发现机制。你不需要把工具列表硬编码给 AI，而是通过协议自动协商：

  1. 服务端注册 (定义能力)
    • 在开发 MCP Server 时，你只需使用对应语言的 SDK（如 Python 的 @mcp.tool() 装饰器）来标记你的函数。
    • SDK 会自动解析函数的名称、注释（Description）和参数类型（Input Schema），将其转化为标准化的元数据。
  2. 初始化握手 (交换能力)
    • 当 AI 宿主启动时，MCP Client 会首先向你的 Server 发送一个 initialize 请求。
    • 随后，Client 会调用标准的 tools/list、resources/list 等 JSON-RPC 接口。
  3. 客户端获取 (注入上下文)
    • 你的 Server 收到 list 请求后，会将所有已注册的工具/资源描述打包返回。
    • MCP Client 拿到这份“菜单”后，会将其注入到大模型（LLM）的系统上下文中。此时，大模型就“知道”了你提供了哪些工具，并能在需要时自动生成符合规范的调用指令。

二、MCP 服务端开发

2.1 核心组件

组件 导入路径 作用
Server @modelcontextprotocol/sdk/dist/cjs/server/index.js MCP 服务端核心类
StdioServerTransport @modelcontextprotocol/sdk/dist/cjs/server/stdio.js STDIO 传输层
CallToolRequestSchema @modelcontextprotocol/sdk/dist/cjs/types.js 工具调用请求处理器
ListToolsRequestSchema @modelcontextprotocol/sdk/dist/cjs/types.js 工具列表请求处理器

2.2 服务端核心结构

const { Server } = require('@modelcontextprotocol/sdk/dist/cjs/server/index.js');
const { StdioServerTransport } = require('@modelcontextprotocol/sdk/dist/cjs/server/stdio.js');
const { CallToolRequestSchema, ListToolsRequestSchema } = require('@modelcontextprotocol/sdk/dist/cjs/types.js');

class FileMcpServer {
  constructor() {
    this.server = new Server(
      { name: 'file-mcp', version: '1.0.0' },
      { capabilities: { tools: {} } }
    );
    this.setupToolHandlers();
  }
  
  setupToolHandlers() {
    // 注册工具列表处理器
    this.server.setRequestHandler(ListToolsRequestSchema, async () => {
      return { tools: [...] };
    });
    
    // 注册工具调用处理器
    this.server.setRequestHandler(CallToolRequestSchema, async (request) => {
      const { name, arguments: args } = request.params;
      // 执行对应工具
    });
  }
  
  async start() {
    const transport = new StdioServerTransport();
    await this.server.connect(transport);
  }
}

三、工具能力注册

3.1 工具定义格式

tool/list 中的一个tool

{
  name: 'read_file',
  description: 'Read the contents of a text file',
  inputSchema: {
    type: 'object',
    properties: {
      file_path: { 
        type: 'string', 
        description: 'The absolute path to the file' 
      },
      encoding: { 
        type: 'string', 
        description: 'File encoding', 
        default: 'utf8' 
      }
    },
    required: ['file_path']
  }
}

3.2 工具注册方式

通过 ListToolsRequestSchema 处理器返回工具列表：

this.server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      { /* 工具1定义 */ },
      { /* 工具2定义 */ },
      // ...更多工具
    ]
  };
});

四、调用协议（JSON-RPC 2.0）

4.1 协议版本

2024-11-05

4.2 核心方法

方法 用途 参数
initialize 初始化连接 protocolVersion, capabilities, clientInfo
notifications/initialized 确认初始化完成 无
tools/list 获取工具列表 无
tools/call 调用工具 name, arguments

4.3 请求格式

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": {
      "file_path": "/path/to/file.txt"
    }
  }
}

4.4 响应格式

成功响应：

{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "文件内容..."
      }
    ]
  }
}

错误响应：

{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "Error: 错误信息"
      }
    ],
    "isError": true
  }
}

五、MCP 客户端开发

5.1 通信方式

通过 标准输入输出（STDIO） 与服务端通信

5.2 初始化流程

  1. 发送 initialize 请求
  2. 接收响应后发送 notifications/initialized

5.3 客户端核心代码

async function sendRequest(request) {
  process.stdout.write(JSON.stringify(request) + '\n');
}

async function initializeConnection() {
  await sendRequest({
    jsonrpc: '2.0',
    id: 0,
    method: 'initialize',
    params: {
      protocolVersion: '2024-11-05',
      capabilities: {},
      clientInfo: { name: 'test-client', version: '1.0.0' }
    }
  });
  
  await sendRequest({
    jsonrpc: '2.0',
    id: 0,
    method: 'notifications/initialized',
    params: {}
  });
}

七、部署与打包

7.1 打包命令

npm run build       # 构建单个平台（Windows）
npm run build:all   # 构建多平台（Windows/Linux/macOS）

7.2 打包配置

{
  "pkg": {
    "assets": [

}

八、开发流程总结

  1. 初始化项目：安装 @modelcontextprotocol/sdk
  2. 定义工具：通过 inputSchema 定义工具参数
  3. 注册处理器：实现 ListToolsRequestSchema 和 CallToolRequestSchema
  4. 启动服务：使用 StdioServerTransport 建立 STDIO 通信
  5. 客户端调用：按 JSON-RPC 协议发送请求
