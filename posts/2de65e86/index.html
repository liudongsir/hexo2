prometheus+grafana

prometheus 开源的监控和警报工具
采用模块化,PUll为主的机构,核心是时序数据采集,存储,查询和告警。

警报依赖于alertManage 或者其他的警报工具类；

grafana 是查询仪表盘,即数据的可视化工具

prometheus核心特性（和传统监控的区别）

时序数据模型：以「指标名 + 标签」的键值对存储时间序列数据（比如 http_requests_total{method=”POST”,status=”200”}），适合监控系统指标；
拉取式采集：Prometheus Server 主动从被监控端（Exporter / 应用）拉取指标，而非被动推送，更易控制采集节奏；
强大的 PromQL 查询语言：支持复杂的指标计算（比如按时间段统计 QPS、错误率）；
本地存储 + 联邦集群：单机可存储，集群可扩展，满足不同规模监控需求；
内置告警规则：可配置告警阈值，触发后推送给 AlertManager 进行告警分发（邮件 / 钉钉 / 企业微信）

主要组成

核心组件
• Prometheus Server：核心，负责采集(pull模式)、存储(内置高性能时序数据库 TSDB,也支持远程数据存储)、查询、告警；
• Exporter：指标暴露器（比如 MySQL Exporter 暴露数据库指标、Node Exporter 暴露服务器指标）即采集数据的客户端；
• Client Library：应用端埋点库（Java 用 micrometer-registry-prometheus库）；
• Pushgateway(推送网关,可选),提供数据上传网关, 任务主动将指标推送至网关,然后server再从网关拉取数据. 适用于短时间任务(批处理,定时任务job,一次性任务等)
• AlertManager：告警管理，负责去重、分组、路由告警；
• Grafana：可视化面板，对接 Prometheus 展示炫酷监控图表（非核心但必备）;prometheus内置webui,可供简单查询图表告警状态查看.
grafana 自带sqllite存储, 主要存储用户,数据源,仪表盘,告警配置.

配合springbootadmin

可以配合springbootadmin 的/actuator接口查询更加详细的应用(微服务)数据, 单独的prometheus更适合查询资源占用等趋势信息.
SBA 做实时运维 查看应用状态,应用日志, 分析故障
prometheus 做趋势分析+告警,例如监控响应时长,

graph LR
A[Spring Boot 应用] –>|暴露 Actuator 接口| B[Spring Boot Admin]
A –>|暴露 Prometheus 指标| C[Prometheus]
C –>|指标数据| D[Grafana]
C –>|告警规则触发| E[AlertManager]

使用:

grafana

配置镜像启动 默认密码 admin/admin
如果启动错误可以充值密码然后重启服务;

配置数据源连接 数据源为 prometheus ip:9090
配置仪表盘;

promethues:

拉取镜像, 配置application.yml 启动服务.

在微服务中引入客户端 启动项目, 并且需要暴露接口.

一个prometheus.yml配置文件

# my global config 全局配置
global:
  scrape_interval:     15s # Set the scrape interval to every 15 seconds. Default is every 1 minute.
  evaluation_interval: 15s # Evaluate rules every 15 seconds. The default is every 1 minute.
  # scrape_timeout is set to the global default (10s).

# Alertmanager configuration  报警配置
alerting:
  alertmanagers:
    - static_configs:
        - targets:
          # - alertmanager:9093

# Load rules once and periodically evaluate them according to the global 'evaluation_interval'.
# 规则文件：未配置规则文件
rule_files:
# - "first_rules.yml"
# - "second_rules.yml"

# A scrape configuration containing exactly one endpoint to scrape:
# Here it's Prometheus itself. 抓取配置 定义了多个作业来抓取不同服务的指标
scrape_configs:
  - job_name: 'Prometheus'
    static_configs:
      - targets: ['cloudhost:9090']

  - job_name: 'Grafana'
    static_configs:
      - targets: ['cloudhost:3000']

  - job_name: 'Nacos'
    metrics_path: '/nacos/actuator/prometheus'
    static_configs:
      - targets: ['cloudhost:8848']
    # monitor 监控的账号密码
    basic_auth:
      username: ruoyi
      password: 123456
# RuoYi-Cloud-Plus 应用监控  通过服务发现端口进行作业 即 springbootadminserver端 扫描微服务;
# /actuator/prometheus 这里是prometheus的客户端访问路径.
  - job_name: RuoYi-Cloud-Plus
    honor_timestamps: true
    scrape_interval: 15s
    scrape_timeout: 10s
    metrics_path: /actuator/prometheus
    scheme: http
    # monitor 监控的账号密码
    basic_auth:
      username: ruoyi
      password: 123456
    http_sd_configs:
      - url: 'http://cloudhost:9100/actuator/prometheus/sd'
        # monitor 监控的账号密码
        basic_auth:
          username: ruoyi
          password: 123456
    relabel_configs:
      # 如果目标有context_path标签，则修改metrics_path以包含该上下文路径
      - source_labels: [__meta_http_sd_context_path]
        target_label: __metrics_path__
        replacement: '${1}/actuator/prometheus'

告警

两者的告警都是通过定时查询, g是查询时序数据库, p是查询客户端读取状态;

一般应用都是使用g告警, p产生数据.
