springgateway

官方文档

2026-02-09
网关基于webflux响应式编程,包含了一系列过滤器和断言的框架,主要处理请求的转发和鉴权,
过程汇总融合了请求的限流 熔断 重试等网络请求限制功能;通过断言的匹配和Filter的处理实现上述功能。

网关配置 过滤器 断言

webflux 响应式编程异步非阻塞.

springgateway 的异步非阻塞

springgateway基于netty的 eventLoop线程池工作;

线程数固定; 非IO操作可复用线程
io操作:等待下游服务, 数据库查询,远程接口调用.

注意这个是线程复用,: 在处理事件A和事件B中,线程不释放,直接复用;
而不是线程切换,在复用过程中,线程变量并不安全, 所以不支持线程变量.
而在webflux的规范中禁止使用阻塞线程操作
线程复用中使用threadLocal 如果没有手动清除会造成内存堆积.

所以响应式编程或者说网关项目中禁用threadlocal 和同步阻塞操作。
一个是线程堆积，
一个是netty的线程是固定了, 如果阻塞会造成事件堆积,即新请求无法处理

springgateway的两类过滤器

WebFilter 是前置过滤，执行时还不知道要转发到哪个下游服务
GlobalFilter 是路由后过滤，执行时已经确定了路由规则，能操作路由相关逻辑。

特性 GlobalFilter (Spring Cloud Gateway 专属) WebFilter (Spring WebFlux 通用)
归属体系 是Spring Cloud Gateway特有的过滤器接口，用于处理网关请求 是Spring WebFlux的标准过滤器接口，用于处理所有Web请求
核心定位 处理网关特有的路由、转发、负载均衡等核心逻辑 处理通用的 Web 请求过滤（和 WebFlux 应用通用）
执行时机 在网关 “路由匹配后、请求转发前 / 后” 执行 在网关 “接收请求后、路由匹配前” 执行
核心入参 ServerWebExchange + GatewayFilterChain ServerWebExchange + WebFilterChain
路由感知 能获取 / 修改路由信息（Route 对象） 无路由信息（执行时还没匹配路由）
优先级控制 通过ordered接口或者@order 同样通过 @order/ordered，但整体早于 GlobalFilter
核心能力 支持网关特有操作（如修改转发地址、添加重试逻辑） 仅支持通用 Web 操作（如修改请求头、记录日志）
适用场景 需要感知路由、修改转发行为、处理网关核心能力的场景 与路由无关、所有请求都需要执行的通用逻辑
路由级别的鉴权（比如不同路由用不同的 token 规则）；
修改转发地址、添加请求参数 / 头（针对特定路由）；
网关层面的限流、熔断、重试；
路由匹配后的日志记录（记录转发的下游服务地址）；
响应结果的统一包装（针对特定路由）。		 全局请求日志（记录所有进入网关的请求，不管最终转发到哪个服务）；
全局跨域配置（CORS）；
全局请求头清洗 / 添加（比如给所有请求加 traceId）；
全局 IP 白名单（拦截非法 IP，无需路由信息）；
请求参数的通用校验（比如所有请求必须带 X-Request-Id）。
场景选择 是否需要路由信息 需要（比如根据路由 ID 做不同逻辑、修改转发地址）→ 选 GlobalFilter；不需要（比如全局日志、跨域、统一加头）→ 选 WebFilter。
通用逻辑优先 WebFilter WebFilter 是 WebFlux 通用标准，逻辑更纯粹，不耦合网关路由细节；比如所有请求的 IP 拦截、traceId 注入，用 WebFilter 更合适。
网关核心能力优先 GlobalFilter 涉及路由、转发、重试、限流等网关特有能力，必须用 GlobalFilter；比如针对某个路由配置限流规则，只有 GlobalFilter 能拿到路由信息。
优先级控制 WebFilter 整体执行早于 GlobalFilter，如果需要 “先拦截、后处理路由”，可以组合使用（比如 WebFilter 做 IP 白名单，GlobalFilter 做路由鉴权）。

两种filter的执行

请求进入网关 →

  1. WebFilter 执行（所有 WebFilter 按优先级执行）→
  2. 网关路由匹配（根据配置找对应的路由）→
  3. GlobalFilter 执行（所有 GlobalFilter 按优先级执行）→
  4. 请求转发到下游服务 →
  5. 响应返回 →
  6. GlobalFilter 反向执行（后置逻辑）→
  7. WebFilter 反向执行（后置逻辑）→
  8. 响应返回给客户端

第二种加入配置文件中路由 断言和filter的执行顺序

springgateway路由转发几种机制:

1: 微服务转发 负载均衡转发 lb://
2.固定地址转发: http://www.baidu.com
3.本地转发:forward:// 网关自身转发,不走网络
4.websocket转发 ws:// wss://
5.重定向: redirect://

springgateway的路由转发:

1.配置路由,
2.webfilter前置过滤请求, 处理请求的共性问题如消息头,参数 sql注入 xss过滤等

  1. 执行断言匹配路由
    4,执行globalfilter springgateway 特有的全局路由 , 主要适应 转发重试限流等网关特有功能.
  2. 执行配置文件中的filter, 主要用于改变http请求和响应, 在GatewayFilter,路由过滤器作用范围是一个特定的路由。

springgateway 微服务中的网络通信协议

路由转发协议根据入口请求协议确定, 例如http转发即使http,tcp udp 即转发tcp udp;
路由转发是通过http请求转发（大部分）
路由通过服务发现解析到具体的地址,直接请求 ReactiveLoadBalancerClientFilter用于解析具体ip:端口号

feign 和dubbo等通信框架只用于微服务之间的通信调用

feign是通过http协议请求转发， dubbo等rpc框架一般是自建协议，效率较高，
feign的负载均衡配合robbin， dubbo自带负载均衡。

springgateway的负载均衡

springgateway负载均衡需要引入springcloudloadbalacnce

scbl 内置负载策略,同时支持自定义策略.

==轮询==: 按顺序分配, 无法适配性能差异 ==默认策略==

==随机==: 转发不均使用测试或者负载小的环境

权重: 为不同实例设置不同权重(需自定义实现), 优点:适配性能差异, 缺点需要手动设置.

响应时间加权: 响应越短被选中概率高(需自定义实现), 适用于对响应延迟敏感的场景,动态适配实例负载 缺点 需要统计响应时间.

最少连接数:适用于长连接场景(需自定义实现) 避免实例过载,确定需要统计连接数.

SCLB仅内置轮训和随机, 其他需要自定义实现。

所有策略都会过滤不健康实例,(心跳失败,接口调用超时),避免转发到不可用节点。

nginx的负载均衡策略

轮询 默认

加权轮询

ip_hash :需要会话保持的

最少连接 :适用于耗时长, 长连接

最短响应: 使用响应要求高
