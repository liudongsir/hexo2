AI应用演化与核心名词手册

一、AI 应用的五阶段演化流程

AI 应用的发展本质上是 \\ 从 “被动回答” 到 “主动干活”\\ 的能力跃迁，每一个阶段都在解决前一阶段的核心痛点，逐步让 AI 从 “会聊天的百科全书” 变成 “能动手的生产力工具”。

阶段 1：基础生成式 AI（2022.11 - 2023.06）

核心定位：会聊天的 “百科全书”

  • 时间节点：以 ChatGPT 发布为起点，大模型首次走向大众

  • 核心能力：纯文本生成、自然语言对话、知识问答

  • 能力边界：只能 “说”，不能 “做”；没有外部交互能力，所有输出都来自训练数据

  • 代表产品：初代 ChatGPT、文心一言早期版本

  • 痛点：知识过时、无法处理实时数据、不能执行操作

阶段 2：工具增强型 AI（2023.06 - 2023.12）

核心定位：学会 “用工具” 的助手

  • 时间节点：OpenAI 推出 Function Calling 能力，大模型首次具备结构化调用外部能力的接口

  • 核心能力：大模型可以理解何时需要调用外部工具，输出结构化的调用请求

  • 能力边界：单步工具调用，需要人类指挥下一步，无法自主完成多步任务

  • 代表技术：Function Calling、代码解释器、早期插件系统

  • 痛点：只能单步执行，复杂任务需要人类全程指挥，无法自动化

阶段 3：流程 AI（Workflow AI）（2023.12 - 2024.12）

核心定位：“按清单办事” 的自动化流水线

  • 时间节点：自主 Agent 技术尚不成熟，行业转向 “可控落地” 的过渡方案

  • 核心能力：将 AI 能力、工具能力编排成预设的固定工作流，AI 按照人类提前设计好的步骤自动执行

  • 能力边界：流程固定，无法灵活应对异常；如果任务超出预设步骤，就会失败

  • 代表产品：n8n、Zapier AI、AI 增强型 RPA、扣子工作流

  • 痛点：不够灵活，流程变更需要重新编排，无法处理未预设的复杂任务

阶段 4：自主 Agent 探索期（2024 全年）

核心定位：尝试 “自己想办法” 的初代智能体

  • 时间节点：开源社区爆发式探索，首次尝试让 AI 自主规划任务步骤

  • 核心能力：AI 可以根据目标，自主拆解任务、规划步骤、处理异常，不需要人类提前写流程

  • 能力边界：技术不成熟，容易产生幻觉、容易卡住、不稳定，无法大规模生产落地

  • 代表项目：AutoGPT、BabyAGI、早期开源 Agent 框架

  • 痛点：稳定性差、安全风险高、可控性弱，只能用于测试，无法商用

阶段 5：Agent 产品化落地期（2025.01 - 至今）

核心定位：稳定、可用、能干活的成熟智能体

  • 时间节点：大厂推出标准化的 Agent 框架与协议，Agent 技术从实验室走向生产

  • 核心能力：

    • 成熟的自主 Agent 执行引擎，稳定可靠

    • 标准化的工具接入协议，生态互通

    • 安全可控的权限管理，支持本地 / 私有部署

  • 能力边界：可以自主完成端到端的复杂任务，比如代码开发、数据分析、桌面操作

  • 代表产品 / 技术：Claude Agent SDK、MCP 协议、LobsterAI（龙虾机器）、Claude Code、Cursor

  • 现状：Agent 正式成为生产力工具，从 “玩具” 变成 “能干活的机器人”

二、核心专业名词全解

🔧 核心技术名词

Function Calling（函数调用）

  • 定义：大模型的基础能力，允许模型将自然语言需求，转换为结构化的外部函数调用请求

  • 作用：让大模型从 “只能生成文本”，变成 “可以调用外部工具”，是所有 Agent 能力的底层基础

  • 落地：OpenAI 2023 年 6 月首次推出，现在已经成为所有大模型的标配能力

Agent Loop（智能体循环）

  • 定义：Agent 的核心运行机制，即 \\ 思考（Think）→ 行动（Act）→ 观察（Observe）\\ 的循环

  • 流程：

    1. 大模型根据目标和当前状态，思考下一步要做什么

    2. 调用工具执行对应的操作

    3. 拿到工具执行的结果，更新状态

    4. 回到第一步，继续循环，直到任务完成

  • 作用：让 Agent 可以自主完成多步任务，不需要人类干预

RAG（检索增强生成）

  • 定义：通过检索私有 / 实时数据，增强大模型生成能力的技术

  • 作用：解决大模型知识过时、没有私有数据的问题，让 Agent 可以访问企业内部数据、实时信息

  • 落地：现在几乎所有企业级 Agent 的标配能力

Tool Calling（工具调用）

  • 定义：比 Function Calling 更宽泛的概念，指 Agent 调用所有外部能力的统称，包括 API、文件操作、命令执行等

  • 区别：Function Calling 是底层的模型能力，Tool Calling 是上层 Agent 的能力抽象

📡 框架与协议名词

MCP（Model Context Protocol，模型上下文协议）

  • 定义：Anthropic 推出的开放标准协议，被称为 “AI 界的 USB-C 接口”

  • 作用：统一大模型与外部工具、数据源的接入标准，解决之前每个工具都要写一套适配代码的问题

  • 能力：定义了工具发现、权限控制、通信格式的标准，让任何工具只要适配 MCP，就可以被所有 Agent 使用

  • 现状：已经捐赠给 Linux 基金会，成为行业通用标准

A2A（Agent-to-Agent Protocol，智能体间通信协议）

  • 定义：Google 推出的开放标准协议，用于不同 Agent 之间的协作通信

  • 作用：解决不同厂商、不同框架开发的 Agent 无法互通的问题，让多个 Agent 可以像团队一样协作干活

  • 核心机制：通过 Agent Card（能力名片）让 Agent 互相发现能力，通过任务流实现协作

  • 现状：2025 年推出，已经捐赠给 Linux 基金会，是多 Agent 系统的核心标准

Claude Agent SDK

  • 定义：Anthropic 官方推出的黑盒式 Agent 执行框架，将 Claude Code 的核心 Agent 能力封装成编程接口

  • 特点：

    • 内置完整的 Agent Loop、工具执行、状态管理

    • 开发者只需要发指令、开权限，不需要自己写 Agent 逻辑

    • 本质是 “现成的 Agent 机器人” 的调用接口，开发者无法控制内部执行逻辑

  • 定位：快速落地 Agent 能力的方案， trade-off 是方便但不可控

File System Access API

  • 定义：浏览器端的 Web API，允许网页在用户授权后，读写本地文件系统

  • 作用：让浏览器端的 Agent 可以直接操作用户的本地文件，不需要上传到服务器，比如 rename.tools、在线 Agent 工具

  • 限制：必须用户手动授权，仅 Chrome/Edge 等现代浏览器支持

📦 产品与项目名词

AutoGPT

  • 定义：2023 年 3 月开源的初代自主 Agent 项目，是 Agent 概念的 “破圈者”

  • 意义：首次向大众展示了 AI 可以自主拆解任务、调用工具、完成复杂目标，引爆了 Agent 领域的热潮

  • 现状：早期探索性项目，稳定性差，现在已经演化为更成熟的商业产品

BabyAGI

  • 定义：与 AutoGPT 同期的开源 Agent 项目，提出了 “任务生成 - 优先级排序 - 执行” 的经典 Agent 架构

  • 意义：奠定了早期 Agent 的基础架构，是很多后续 Agent 框架的原型

LobsterAI（龙虾机器 / OpenClaw）

  • 定义：网易有道推出的开源、本地优先的桌面级 Agent 产品，2026 年初爆火

  • 技术架构：

    • 上层：UI 界面、IM 网关、会话管理

    • 底层：基于 Claude Agent SDK 作为执行引擎

    • 能力：本地文件操作、命令执行、桌面 GUI 操作、跨 IM 协作

  • 定位：Agent 产品化的典型代表，把大厂的 Agent 能力包装成普通人可以直接用的桌面工具

GPTs

  • 定义：OpenAI 推出的自定义 Agent 平台，允许用户无代码创建自己的定制化 GPT

  • 能力：用户可以添加自定义知识、工具、指令，快速搭建轻量的垂直 Agent

  • 特点：低代码、生态化，是普通用户创建 Agent 的入门方案

Claude Code

  • 定义：Anthropic 推出的命令行式代码 Agent，是 Claude Agent SDK 的官方落地产品

  • 能力：可以自动读代码、改 Bug、写测试、执行命令，是开发者的 AI 编程助手

  • 本质：Anthropic 把自己的 Agent 能力，做成了面向开发者的直接可用的工具

Cursor

  • 定义：基于 Agent 的 AI 代码编辑器，内置了自主 Agent 能力

  • 能力：可以理解整个项目的代码，自动重构、修复 Bug、生成功能，是代码 Agent 的代表产品

三、演化的核心逻辑：从 “人适应 AI” 到 “AI 适应人”

整个演化过程的本质，是交互成本的不断降低：

  1. 生成式 AI：你要学会怎么写 Prompt，让 AI 听懂你

  2. 工具 AI：你要学会怎么指挥 AI 用工具

  3. 流程 AI：你要学会怎么给 AI 排流程

  4. Agent AI：你只需要说你要什么，AI 自己搞定所有事

未来的方向，就是让 AI 真正像一个员工一样，你只需要给目标，它自己想办法完成，不需要你教它怎么做。
